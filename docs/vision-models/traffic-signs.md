# Traffic-Sign Detection

## Status

Capability: `traffic_signs`
Current status: `MODEL_NOT_CONFIGURED`
Model, artifact, class map, and inference implementation: not selected or available.

The API reports traffic-sign detection as unavailable. No traffic-sign labels or boxes are generated by EDAS Vision Lab today.

## Requirements for a future implementation

- Define the supported sign taxonomy (including local sign variants, temporary signs, and speed-limit classes) with domain review.
- Select a legally usable detector and document artifact/version/checksum, class mapping, input requirements, and license.
- Collect representative daylight/night, rain, glare, occlusion, distance, and motion-blur examples from permitted sources.
- Evaluate per-class precision/recall and missed-critical-sign rates on human-reviewed Pune data.
- Define a confidence/uncertainty policy and keep all outputs in the common event stream.
- Treat signs as informational observations, not driver commands; do not present them as certified navigation or safety advice.

Only mark ready after actual inference and evaluation have passed on the target runtime.
